# バーガーキングの栄養成分（数値だけ）の取り込み (2026-11-28)

## 背景と判断
- バーガーキングはチェーン追加時 (2026-11-08) の調査で「公式の規約が複製・転載を禁じている」ため、説明文・画像・栄養・アレルゲンを一切扱わず、商品ページは公式へのリンクだけにしていた。
- 2026-11-28にオーナーが「数値だけ取る形で進める」と決定。範囲は栄養の数値のみ・出典明記。説明文・画像・アレルゲンは引き続き持ち込まない。価格などの事実は既に記録しており、松屋で規約リスクを聞いた上で進めた前例もある。
- 出典は公式PDF「商品の栄養成分及びアレルゲン情報」(全商品の表。列は製品重量・エネルギー・たんぱく質・脂質・炭水化物・食塩相当量・ナトリウム+アレルゲン記号28列)。

## 変えたこと
- `scripts/pdf_nutrition.py`:
  - `parse_burgerking_nutrition(pages)` を追加。横向きA4・複数表のPDFから、数値の x の集まりで7列を決めて行を作る (見出しは「製品重量 エネルギー たんぱく質」のように1文字列にまとまっていて列位置に使えないため)。商品名は x=100〜280、アレルゲン記号の列 (中心 x≧452) は数値の範囲から外してある。同じ文字列・同じ座標の重複 (太字の重ね描き) は落とす。版は本文の「最終更新日」(2026.11.06 形式) から取る。block は x<100 の題名・節見出しで区切る。
  - `burgerking_alias_name(name)` を追加。記録名の英語表記 (Big Mouth・Special・Mushroom・Garlic・Jr.・American) と「4pc」を PDF のカタカナ表記に寄せる別名変換。
  - `build_nutrition` の nut() に weight_other → other「製品重量」、sodium_other → other「ナトリウム」を追加 (フレッシュネスの糖質と同じ方式。他チェーンの行には無いキーなので影響なし)。
  - `validate_source` の対象に burgerking_nutrition を追加 (エネルギー検算の通過率と更新日の必須)。
- `scripts/pdf_update.py`:
  - `_specs` に burgerking を追加 (kind burgerking_nutrition、注記 BURGERKING_NOTE「栄養成分表の数値は配合に基づいた標準値です。」)。
  - 反映 (step 3) に burgerking の分岐を追加。版テキストは「YYYY年M月D日更新」。
  - `_apply_nutrition` に任意引数 `aliases` を追加 (デフォルト None で従来どおり)。完全一致が無いときだけ別名でも完全一致を試す。部分一致はしない。
- `scripts/crawl.py`: 巡回後の run_pdf_step の対象に burgerking を追加。チェーン節のコメントを実態に合わせて更新。
- `config.json`: `burgerking_pdf` を追加 (nutrition = 2026-11-06版のURL、nutrition_label = 栄養成分及びアレルゲン情報)。
- `scripts/generate_site.py`: バーガーキングの「栄養なし」分岐のコメントを実態に合わせて更新 (表示文言は変更なし。栄養が付いた商品は従来どおり通常の表+出典表示になる)。
- `README.md`: バーガーキングの節を更新 (下記の URL の注意を含む)。
- テスト: `tests/pdf_fixtures.py` に burgerking_page、`tests/test_burgerking_nutrition.py` (6件) を追加。

## URL が版ごとに変わる件
- PDFのURLは `/images/org/pdf/YYYY/MM/DD/<UUID>.pdf` で、版ごとにパスもファイル名も変わる (2026-10-16版と2026-11-06版で確認)。サイト内に固定の案内ページは見つからず (SPAで、内部APIにもPDFへの手がかりは未確認)、自動で新しいURLを発見する手段は無い。
- そのため config の URL が現在の版を指す形にした。新しい版が出て旧URLが消えると、HEAD/GET の失敗が pending に残るので、それを合図に config の URL を差し替える運用 (おおむね月1回)。版そのものの判定はPDF本文の「最終更新日」で行うので、差し替えさえすれば同じ版の再取り込みは起きない。

## 検証
- 合成フィクスチャのテスト6件が通る。全テスト 829件で、失敗は従来からの test_regular.py の13件 (10 FAIL + 3 ERROR) のみ。
- 実物 (2026-11-06版PDF・実データ22件) で pdf_update.update_chain を試走: 15件に栄養が付き、エラーなし。値は検索インデックスに残るPDF本文とも一致 (ビーフ＆ダブルハッシュ ビッグマウスギルティ 1,072kcal・たんぱく質37.1・脂質75.4・炭水化物60.7・食塩4.7、ギルティ ザ・ワンパウンダー 製品重量513g)。PDF全体は125行・エネルギー検算の通過率100%。
- 生成HTMLの確認: 栄養が付いた商品は表 (熱量・たんぱく質・脂質・炭水化物・食塩相当量・製品重量・ナトリウム) + 公式の注記 + 出典 (公式PDFへのリンクと版) が出ることを render_nutrition で確認した。

## 一致しなかった7件 (実測)
- ビッグバーレル2件: PDFに載っていない。
- My Premiumショコラ チョコ＆キャラメル: PDF側は「わたくしのプレミアムショコラ チョコレート＆キャラメル」で、別名変換では寄せきれない。無理に当てない。
- チーズチキンナゲット: PDFには個数違い (5ピース等、ソース抜き) しかなく、どれか1つに決められない。
- にんにく3件: 2026-11-27発売で、この版 (11-06) には未掲載。次版で載れば、うち2件は別名変換 (Garlic→ガーリック) で一致する見込み。

## やらなかったこと・未確認のこと
- アレルゲンは取り込んでいない (オーナー決定の範囲外)。
- 本番の巡回での反映は未確認 (マージ後の定期巡回または手動 update で入る。初回は HEAD の指紋が無いため必ず取得する)。
- 公式サイトの内部APIにPDFのURLが含まれていないかは未確認 (2026-11-28の調査でAPIへの問い合わせがタイムアウトしたため)。もし含まれていれば、URLの自動発見に差し替えられる。
